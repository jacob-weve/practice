## 1. 제품 개요

### 1.1 한 줄 정의
**AI 기반 맞춤형 말투 변환 및 감정 분석 메시지 코칭 서비스**

### 1.2 문제 정의
- 메신저/SNS의 텍스트 소통에는 표정·억양이 없어서 **같은 문장도 차갑거나 공격적으로 읽힐 수 있다.**
- 감정이 격한 상태에서 쓴 답장은 **관계 갈등, 업무상 오해, 거절 실패**로 이어지기 쉽다.
- 상대방의 짧은 답(예: "ㅇㅇ", "알겠어요.")이 **어떤 의도인지 해석하기 어려워** 불안을 느끼는 사용자가 많다.

### 1.3 핵심 가치
1. **오해 방지**: 오해를 부르는 단어나 문장을 보내기 전에 찾아낸다.
2. **의도 보존**: 사용자의 원래 의도(거절, 요청, 사과 등)는 그대로 두고 표현만 부드럽게 바꾼다.
3. **목적 적합성**: 상황(업무, 연인, 가족, 친구)과 목적에 맞는 페르소나로 다시 쓴다.
4. **프라이버시 우선**: 대화 내용은 기본적으로 서버에 저장하지 않는다(Stateless).

### 1.4 성공 지표 (KPI)
| 지표 | 목표 (출시 후 3개월) |
|---|---|
| 변환 결과 채택률 (복사/공유 클릭) | ≥ 45% |
| 첫 토큰 도달 시간 (TTFT, p95) | ≤ 1.5초 |
| 전체 변환 완료 시간 (p95) | ≤ 6초 |
| 소셜 로그인 성공률 | ≥ 98% |
| D7 리텐션 | ≥ 25% |
| 요청 1건당 평균 LLM 비용 | ≤ $0.004 |

## 3. 유즈케이스

### UC-01. 소셜 로그인으로 가입하기
- **Actor**: 신규 사용자
- **흐름**: 앱 실행 → 로그인 화면에서 카카오/구글/네이버 선택 → 제공자 인증 및 동의 → 필수 약관 동의 → 홈 진입
- **예외**: 사용자가 동의를 취소하면 로그인 화면으로 돌아간다. 같은 이메일로 다른 제공자 계정이 있으면 계정 연결 안내를 띄운다.

### UC-02. 답장 초안 말투 변환
- **Actor**: 로그인 사용자
- **흐름**:
  1. 상대방 메시지(Context)를 입력한다. 텍스트 붙여넣기 또는 스크린샷 업로드(OCR) 모두 가능하다.
  2. 답장 초안(Draft)을 입력한다.
  3. 페르소나(다정다감 / 공손 / 정중한 거절 / 유머러스 / 간결 업무체 등)와 출력 언어를 고른다.
  4. 결과가 스트리밍으로 표시된다: 감정 온도 → 독소 하이라이트 → 변환 문장 3종 순서.
  5. 마음에 드는 문장을 복사하거나 공유한다.
- **결과**: 감정 분석, 독소 감지, 변환 3종을 **LLM 1회 호출**로 받는다.

### UC-03. 감정 온도계 & 독소 조항 확인
- **흐름**: 초안을 입력하고 "분석만 하기"를 누른다 → 0~100°C 온도 게이지와 위험 단어/문장 하이라이트, 각 하이라이트별 대체 표현 제안이 나온다.

### UC-04. 상대방 답장 심리 해석
- **흐름**: 상대방 메시지(와 선택적으로 앞뒤 대화)를 입력한다 → 가능한 해석 여러 개와 각각의 확률/근거, 객관적 가이드, 추천 답장 3종이 나온다.
- **원칙**: 단정하지 않는다("~일 가능성이 있어요"). 상대방을 비하하거나 조종하는 조언은 하지 않는다.

### UC-05. 히스토리 확인
- **흐름**: 이전 변환 결과는 **기기 로컬 저장소**에서 불러온다. 서버 동기화는 사용자가 명시적으로 켠 경우에만 하며(Opt-in), PII는 마스킹한다.

### UC-06. 회원 탈퇴 및 데이터 삭제
- **흐름**: 설정 → 탈퇴 → 재확인 → 서버 데이터 즉시 파기(로그는 법정 보관 항목만 남김) → 소셜 제공자 연결 해제(Unlink/Revoke API 호출)

## 4. 기능 요구사항

### 4.1 [F-AUTH] 소셜 로그인 및 회원관리

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F-AUTH-01 | 카카오, 구글, 네이버 3개 제공자로 로그인 및 자동 회원가입을 지원한다 | P0 |
| F-AUTH-02 | 모든 제공자에 **OAuth 2.0 Authorization Code + PKCE (S256)** 흐름을 적용한다 | P0 |
| F-AUTH-03 | OIDC를 지원하는 제공자(구글, 카카오)는 `id_token`의 서명(JWKS), `iss`, `aud`, `exp`, `nonce`를 검증한다 | P0 |
| F-AUTH-04 | 네이버는 OIDC 미지원이므로 Access Token으로 프로필 API를 호출해 신원을 확인한다 | P0 |
| F-AUTH-05 | 사용자는 `(social_provider, provider_user_id)` 쌍으로 식별한다. 이메일은 식별자로 쓰지 않으며, 이메일 미제공 시에도 가입이 가능해야 한다 | P0 |
| F-AUTH-06 | 서비스 자체 JWT를 발급한다: Access Token(15분), Refresh Token(14일, Rotation 적용) | P0 |
| F-AUTH-07 | Refresh Token 재사용이 감지되면 해당 사용자의 모든 세션을 폐기한다(Token Family Revocation) | P0 |
| F-AUTH-08 | 필수 약관(서비스 이용약관, 개인정보 처리방침)과 선택 약관(마케팅 수신)에 대한 동의 이력을 버전별로 저장한다 | P0 |
| F-AUTH-09 | 한 사용자에게 여러 제공자 계정을 연결할 수 있다(Account Linking). 단 이메일이 같다고 자동 병합하지 않는다 | P1 |
| F-AUTH-10 | 탈퇴 시 제공자별 연결 해제 API를 호출한다(카카오 unlink, 구글 revoke, 네이버 delete token) | P0 |
| F-AUTH-11 | 만 14세 미만은 가입을 제한한다(연령 확인 동의 체크) | P0 |

**제공자별 수집 항목 (최소 수집 원칙)**

| 제공자 | 필수 수집 | 선택 수집 | 비고 |
|---|---|---|---|
| 카카오 | 회원번호(sub) | 이메일, 닉네임 | 비즈 앱 전환 시 이메일 필수 동의 가능 |
| 구글 | sub | email, name | scope: `openid email profile` |
| 네이버 | id | email, nickname | OIDC 미지원, 프로필 API 사용 |

### 4.2 [F-TONE] 맞춤형 말투 변환 엔진

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F-TONE-01 | 입력: 상대방 메시지(Context, 선택), 답장 초안(Draft, 필수), 페르소나, 관계 유형, 출력 언어 | P0 |
| F-TONE-02 | 스크린샷을 업로드하면 OCR로 텍스트를 추출한다. **이미지는 서버에 저장하지 않고** 처리 후 즉시 폐기한다 | P1 |
| F-TONE-03 | 원래 의도(Intent: 수락/거절/요청/사과/정보전달 등)를 먼저 분류하고, 변환 결과가 그 의도를 유지하는지 확인한다 | P0 |
| F-TONE-04 | 변환 결과는 **3종**이다: ① 선택 페르소나 기본형 ② 더 부드러운 버전 ③ 더 간결한 버전 | P0 |
| F-TONE-05 | 결과는 SSE로 스트리밍한다. 첫 이벤트는 1.5초 안에 도달해야 한다(p95) | P0 |
| F-TONE-06 | 기본 페르소나: 다정다감, 공손, 정중한 거절, 간결 업무체, 유머러스, 사과 | P0 |
| F-TONE-07 | 지원 언어 간 교차 변환(예: 영어 초안 → 한국어 공손체)을 지원한다 | P1 |
| F-TONE-08 | 각 변환 결과에 "왜 이렇게 바꿨는지" 짧은 설명(1문장)을 붙인다 | P1 |

| F-EMO-03 | 오해를 부르는 단어/문장을 **문자 오프셋(start, end)** 단위로 하이라이트하고 유형(비꼼, 단정, 명령조, 수동공격, 비하 등), 심각도(low/medium/high), 대체 표현을 제공한다 | P0 |
| F-EMO-04 | 온도 구간별 색상: 0–30 파랑(차가움), 31–60 초록(적정), 61–80 주황(주의), 81–100 빨강(위험) | P1 |

## 5. 다국어 지원 (i18n) 정의

### 5.1 지원 범위
| 구분 | 1차 (MVP) | 2차 |
|---|---|---|
| **UI 언어** | 한국어(ko), 영어(en) | 일본어(ja), 중국어 간체(zh-CN) |
| **변환 입출력 언어** | ko, en, ja | zh-CN, es, vi |

### 5.2 정책
- UI 언어는 `Accept-Language` → 사용자 설정 → 기본값(ko) 순으로 결정한다.
- **UI 언어와 변환 출력 언어는 따로 설정한다.** 예: 영어 UI로 한국어 공손체 결과를 받을 수 있다.
- 페르소나 이름과 설명, 독소 유형 레이블, 에러 메시지는 모두 i18n 키로 관리한다(하드코딩 금지).
- 언어별 존댓말 체계를 반영한다: 한국어(해요체/하십시오체/반말), 일본어(です・ます/敬語), 영어(formality level).
- 날짜, 숫자, 온도 단위는 로케일 포맷을 따른다(온도는 °C 고정, 레이블만 번역).

## 6. 비기능 요구사항

### 6.1 성능
| ID | 요구사항 |
|---|---|
| NFR-PERF-01 | 변환 API TTFT p95 ≤ 1.5초, 완료 p95 ≤ 6초 |
| NFR-PERF-02 | 인증 API p95 ≤ 300ms(제공자 왕복 시간 제외) |
| NFR-PERF-03 | 동시 접속 1,000 세션까지 수평 확장으로 대응 |

### 6.2 보안
| ID | 요구사항 |
|---|---|
| NFR-SEC-01 | 모든 통신은 TLS 1.2 이상 |
| NFR-SEC-02 | OAuth 2.0 PKCE(S256), `state`(CSRF 방지), `nonce`(재생 공격 방지) 필수 |
| NFR-SEC-03 | Refresh Token은 DB에 **해시(SHA-256)로만** 저장하고 원문은 저장하지 않는다 |
| NFR-SEC-04 | 웹에서는 Refresh Token을 `HttpOnly; Secure; SameSite=Strict` 쿠키로 전달하고, 모바일에서는 OS Secure Storage에 저장한다 |
| NFR-SEC-05 | **프롬프트 인젝션 방어**: 입력 Guardrail 레이어를 두고, 시스템 지침과 사용자 입력을 구조적으로 분리하며, 출력 스키마를 검증한다 |
| NFR-SEC-06 | 요청 속도 제한: 사용자당 변환 30회/분, 일 300회(무료 플랜) |
| NFR-SEC-07 | 입력 길이 제한: Context 2,000자, Draft 1,000자 |

### 6.3 프라이버시
| ID | 요구사항 |
|---|---|
| NFR-PRIV-01 | 변환 요청의 원문은 **기본적으로 서버에 저장하지 않는다(Stateless)** |
| NFR-PRIV-02 | 품질 개선용 로그는 PII 마스킹(이름, 전화번호, 이메일, 주소, 계좌번호, 주민번호) 뒤에만 저장하고, 사용자가 동의한 경우에만 수집한다 |
| NFR-PRIV-03 | LLM 제공사 API는 **학습 미사용(Zero Data Retention 또는 동등 조건)** 계약/설정으로 사용한다 |
| NFR-PRIV-04 | 개인정보 처리방침에 수집 항목, 목적, 보관 기간, 국외 이전(LLM API) 사실을 명시한다 |
| NFR-PRIV-05 | 마스킹 로그는 90일 후 자동 파기하고, 탈퇴 시 즉시 파기한다 |
| NFR-PRIV-06 | 애플리케이션 로그(stdout)에 토큰, 이메일, 대화 원문을 남기지 않는다 |

### 6.4 가용성/운영
- 월간 가용성 99.5% 이상
- LLM 제공사 장애 시 대체 모델로 자동 Fallback
- 구조화 로그와 요청 ID(`X-Request-ID`) 기반 추적

### 6.5 비용
- 요청 성격에 따라 경량 모델과 고성능 모델을 나눠 쓴다.
- 감정 분석 + 독소 감지 + 변환 3종을 **JSON Mode 단일 호출**로 처리해 호출 수를 1/3 이하로 줄인다.

## 7. 트레이드오프 결정 요약

| 트레이드오프 | 결정 | 근거 |
|---|---|---|
| Latency vs Quality | JSON Mode 단일 호출 + SSE 스트리밍 + 비동기 I/O | 호출 횟수와 비용을 줄이고, 체감 지연은 스트리밍으로 숨긴다 |
| Freedom vs Security | 입력 Guardrail + 프롬프트 영역 분리 + 출력 스키마 검증, OAuth PKCE + 짧은 Access Token과 Refresh Rotation | 자유 입력 서비스의 인젝션/탈옥 위험과 토큰 탈취 위험을 줄인다 |
| Privacy vs Data Collection | Stateless 기본, Opt-in 마스킹 로그, 클라이언트 히스토리 | 대화 내용은 민감 정보라 신뢰가 서비스의 핵심이다 |
| Cost vs Scalability | 경량 모델(Guardrail, 라우팅, 분석)과 고성능 모델(변환, 해석)의 역할 분담 | 트래픽이 늘어도 단가를 통제할 수 있다 |

## 8. MVP 범위

MVP는 §4의 **P0 요구사항만** 구현한다. 사용자가 "로그인 → 초안 입력 → 분석·변환 결과 확인 → 복사"까지 한 번에 끝낼 수 있는 것이 목표다.

### 8.1 MVP 핵심 기능

| # | 기능 | 사용자가 할 수 있는 것 | 포함 요구사항 |
|---|---|---|---|
| 1 | **말투 변환** (핵심) | 상대방 메시지(선택)와 답장 초안을 텍스트로 넣고, 페르소나·관계·출력 언어를 골라 변환 문장 3종(기본형 / 더 부드럽게 / 더 간결하게)을 스트리밍으로 받는다. 원래 의도(거절·요청·사과 등)는 유지된다 | F-TONE-01, 03, 04, 05, 06 |
| 2 | **감정 온도계 & 독소 감지** | 초안의 감정 온도(0~100°C)와 변환 후 예상 온도, 감정 레이블을 보고, 오해를 부를 표현의 하이라이트(유형·심각도·대체 표현)를 확인한다. 변환과 같은 LLM 호출 1회로 함께 받으며 "분석만 하기"도 가능하다 | F-EMO-01, 02, 03 |
| 3 | **상대방 답장 해석** | 상대방 메시지(와 앞뒤 맥락)를 넣고, 해석 후보 2~3개(가능성·근거), 과잉 해석 경고, 추천 답장 3종(확인형 / 공감형 / 가벼운 전환형)을 받는다 | F-REPLY-01 ~ 05 |
| 4 | **소셜 로그인 & 회원관리** | 카카오·구글·네이버로 가입/로그인하고, 약관에 동의하고, 탈퇴하면 데이터 파기와 제공자 연결 해제가 이뤄진다 | F-AUTH-01 ~ 08, 10, 11 |
| 5 | **로컬 히스토리** | 이전 결과를 기기 로컬 저장소에서 다시 본다(서버 저장 없음) | F-HIST-01 |

**MVP에서도 지켜야 하는 비기능 요구사항**
- 프라이버시: 변환 원문 서버 미저장(NFR-PRIV-01), LLM 학습 미사용 설정(NFR-PRIV-03), 로그에 토큰·대화 원문 금지(NFR-PRIV-06)
- 보안: 프롬프트 인젝션 방어와 출력 스키마 검증(NFR-SEC-05), 속도 제한(NFR-SEC-06), 입력 길이 제한(NFR-SEC-07), 토큰 저장 방식(NFR-SEC-03, 04)
- 성능: TTFT p95 ≤ 1.5초, 완료 p95 ≤ 6초(NFR-PERF-01)
- 다국어: UI ko/en, 변환 입출력 ko/en/ja(§5.1 1차). 단 언어 간 교차 변환(F-TONE-07)은 MVP 이후
